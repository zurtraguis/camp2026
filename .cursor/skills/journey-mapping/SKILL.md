# Journey Mapping

Visualize how a user (or internal stakeholder) moves toward a goal, exposing friction and opportunities before design.

## When to Use This Skill

- Internal-app stakeholder mapping (replaces market research for internal tools)
- Understanding an end-to-end flow before designing screens
- Locating drop-off, friction or redundant steps
- Aligning a team on "who does what, when, and why"

## How to Build a Map

For each **persona + goal**, lay out stages left-to-right:

| Stage | User actions | Touchpoints | Thoughts/Emotions | Pain points | Opportunities |
|-------|--------------|-------------|-------------------|-------------|---------------|

1. **Define the actor and the goal** (one journey = one persona + one goal).
2. **List stages** chronologically (Awareness → … → Outcome).
3. **Capture actions and touchpoints** per stage (systems, screens, people).
4. **Note emotion and friction** — where does it get hard or confusing?
5. **Derive opportunities** — turn each pain point into a candidate requirement.

## Outputs

- A journey table/diagram per key persona
- A prioritized list of pain points → opportunities (impact × effort)
- Inputs that feed the PRD, design states, and acceptance criteria

## Anti-patterns

- One "average user" journey that hides distinct personas
- Mapping the happy path only (ignore error/recovery flows)
- Opportunities with no link to a concrete requirement
